# 디노테푸란 검사 우선순위 예측

검사 결과를 알기 전에 이용 가능한 정보로 디노테푸란 잔류 위험을 예측합니다. **잔류 존재**, **MRL(잔류허용기준)의 10% 초과**, **기준 부적합**은 의미와 분석 대상이 달라 각각 별도의 이진분류 문제로 다룹니다. 모델 출력은 검사·검토 우선순위를 돕는 신호이며, 적합·부적합의 확정 판정이 아닙니다.

| 항목 | 현재 기준 |
|---|---|
| 분석 단위 | 검사 결과 1건 (`record_id`) |
| 통합원장 | 428,214건, `record_id` 중복 없음 |
| 목표 | `occurrence` · `screening` · `noncompliance` |
| 모델 | Logistic Regression · CatBoost · LightGBM · XGBoost · LSTM |
| 분할 | 학습 2015~2024년 · 검증 2025년 · 최종 평가 2026년 상반기 |
| 현재 상태 | 공식 Core 기준선, 튜닝 v1·기상 v2, 후보 잠금 및 최종 평가 완료 |

정확도(Accuracy) 하나로 판단하지 않습니다. 목표마다 양성 비율과 검사 우선순위의 의미가 다르므로 **Recall을 우선 확인하되 Precision·F2·평균 정밀도(AP)·오탐 부담을 함께** 봅니다. 서로 다른 목표나 서로 다른 연결 가능 모집단의 점수를 단순 순위로 비교하지 않습니다.

## 1. 데이터와 목표

| 목표 | 양성의 의미 | 확정 분석 대상 | 용도 |
|---|---|---:|---|
| `occurrence` | 디노테푸란 잔류 존재 | 364,864건 | 전체 시료 잔류 발생 감시 |
| `screening` | 검사 결과 / MRL **> 0.1** | 67,262건 | 검사 우선순위의 주 목표 |
| `noncompliance` | 잔류허용기준 부적합 | 127,761건 | 규제 위험 보조 경보 |

`screening`은 MRL에 연결되고 수치 기준을 판단할 수 있는 시료만 대상으로 합니다. 비율이 **정확히 0.1이면 음성**, 0.1을 **초과해야 양성**입니다. 미확정 판정이나 필요한 수치가 없는 행을 임의로 음성(0)으로 바꾸지 않습니다. 이 때문에 세 목표의 분석 대상 건수도 서로 다릅니다.

무작위 행 분할 대신 시간에 따라 학습(2015~2024년), 검증(2025년), 최종 테스트(2026년 1월 1일~6월 30일)를 나눕니다. 동일 `duplicate_group_id`는 한 분할에만 배치합니다. 카테고리·결측 처리 규칙은 학습자료에만 맞추고, 검사 결과·판정·MRL 비율·사후 생성 정보는 입력 변수에서 제외합니다. 상세한 허용 변수는 위 `feature_policy.yaml`을 기준으로 합니다.

## 2. 설치와 설정

저장소 루트에서 환경을 준비한 뒤 `train`을 작업 디렉터리로 사용합니다.

```powershell
conda env create -f environment.yml
conda activate dinotefuran
cd train
Copy-Item .env.example .env
```

이미 동일한 환경이 있으면 환경 생성 단계는 건너뜁니다. `.env`의 `DINO_EDA_DATA_PATH`에 접근 권한이 있는 통합원장 CSV 경로를 지정합니다. 실제 데이터와 `.env`에는 개인 경로·접속정보가 포함될 수 있으므로 **커밋하지 않습니다**. 이 공개 저장소에는 원천 데이터·DB 접속값·모델 체크포인트·실행 산출물을 넣지 않았습니다. 따라서 공개 코드만으로 과거 성능표를 처음부터 재생성할 수는 없습니다.

## 4. 실행·상태 확인

처음에는 **코드와 공개 집계 결과를 확인**합니다. 비공개 `output/`이 없는 새 클론에서 `status`는 과거 trial을 보여주지 않습니다. 최종 테스트는 이미 후보를 잠근 뒤 평가했으므로 README의 시작 명령에 재평가를 넣지 않습니다.

```powershell
# train/에서 실행: 사용 가능한 명령과 완료 trial 확인
python -m tuning --help
python -m tuning status
python -m tuning_v2_weather --help
python -m tuning_v2_weather status

# 정책·경계·CLI 등 단위 테스트
python -m unittest discover -s tests -p test_*.py -v
```

분석을 새 데이터로 다시 수행할 때는 `eda` → `pre_modeling` → `feature_engineering` → 베이스라인·외부변수 점검 → `tuning` 순으로 진행합니다. 먼저 `python -m tuning validate`로 실험대장·탐색공간·입력을 검증하고, 실제 튜닝이 필요할 때만 작은 smoke run으로 저장·재시작 경로를 확인합니다. `run`, `lock-final`, `evaluate-final`, `evaluate-shared-test`는 실험 상태나 테스트 사용 이력을 바꾸므로 기존 최종 결과를 단순 조회할 목적으로 실행하지 않습니다.

| 결과 위치 (`train/` 기준) | 내용 |
|---|---|
| `output/official_baseline_core_v1/` | 동일 조건의 5개 모델 Core-only 공식 비교선 |
| `resources/tuning_experiment_registry.csv` | A1 Core 15개, A2 내부 고도화 12개, B 외부 민감도 11개 구성의 고정 실험대장 |
| `output/tuning_v1/` | 38개 구성의 탐색 기록·내부 후보 잠금·목표별 최종 평가 |

`output/`에는 원장 유래 자료와 모델이 포함될 수 있어 Git에서 제외했습니다. 위 경로는 원본 분석 환경에서 검증된 산출물 위치이며, 새 클론에는 기본으로 존재하지 않습니다. 공개본에서는 `results/`의 집계표, `train/resources/`의 고정 실험대장과 `train/HANDOVER.md`를 참고합니다. 특히 외부변수 B 실험 전체를 재실행하려면 공개본에서 제외한 과거 기상 창 선택 결과와 중간 연결 자료가 필요합니다. 원본 산출물을 요구하는 일부 테스트는 자료가 없으면 건너뜁니다.

## 5. 확정 결과

공식 Core-only 기준선은 **공통 비교 참조선**입니다. 튜닝 v1에서는 2025년 검증자료만 사용해 각 목표의 내부 최종 후보와 임계값을 고정한 뒤, 2026년 상반기에 한 차례 평가했습니다. 아래 성능은 목표마다 **서로 다른 확정 모집단**의 결과이며, 목표 사이 우열을 뜻하지 않습니다.

| 목표 | 고정 후보 | 2026 상반기 n (양성) | Recall | Precision | F2 | AP |
|---|---|---:|---:|---:|---:|---:|
| 잔류 존재 | CFG-010 · XGBoost | 34,142 (1,532) | 0.719 | 0.135 | 0.386 | 0.216 |
| MRL 10% 초과 | CFG-018 · CatBoost | 2,375 (436) | 0.880 | 0.269 | 0.605 | 0.393 |
| 기준 부적합 | CFG-031 · CatBoost | 8,914 (24) | 0.413 | 0.322 | 0.391 | 0.167 |

출처: [공개 집계표](results/final_model_test_metrics.csv). 수치는 표에서 소수 셋째 자리로 반올림했습니다. 기준 부적합의 테스트 양성은 24건뿐이므로 성능의 불확실성이 큽니다.

기상 v2는 **국내 기상 연결이 가능한 동일 시료**에서만 내부 변수 대조군과 비교했습니다. 2025년 검증에서 WV2-007(LightGBM, 60일)을 Recall 우선 기상 후보로 잠갔고, WV2-003(CatBoost, 60일)은 신규 자료에서 다시 확인할 보조 후보로 남겼습니다. 잠긴 WV2-007을 2026년 상반기 공통 789건(양성 150건)에 적용했을 때 Recall은 내부 대조군 0.773에서 0.960으로 높아졌으나, 거짓 양성(FP)도 337건에서 502건으로 늘었습니다. 이는 **전체 screening 2,375건 결과와 다른 연결 가능 하위 모집단**의 비교이며, 기상 추가가 전체 검사 대상에서 같은 효과를 낸다는 뜻은 아닙니다. F2와 AP 차이의 신뢰구간도 0을 포함합니다.

## 6. 평가 원칙과 한계

- 임계값은 각 후보의 **2025년 검증자료에서 가중 F2가 최대인 지점**으로 정합니다. Recall만 높이고 검사 부담을 과도하게 늘리는 선택을 피하기 위해 Precision·F2·AP와 혼동행렬도 함께 봅니다.
- Optuna 탐색과 후보 선택은 검증자료에서 수행했습니다. 2026년 상반기 테스트 점수를 본 뒤 후보·변수·임계값을 다시 고르지 않습니다. 추가 비교는 신규 전향자료에서 수행해야 합니다.
- 국내 기상은 생산지·생산일이 없으면 수거지·수거일의 대리정보이고, 수입 기후평년은 실제 검사연도의 날씨가 아닙니다. 기상·기후 변수의 중요도는 인과효과로 해석하지 않습니다.
- 기상 v2의 789건 결과는 연결 가능 시료에 한정됩니다. 기준 부적합 양성의 희소성, 출처별 결측, 규정 시점 자료의 제약도 운영 확대 전에 재확인해야 합니다.

기존 결과와 공개본의 재현 범위를 자세히 확인할 때는 [`train/HANDOVER.md`](train/HANDOVER.md)를 참조합니다. 최종 근거 패키지의 상세 manifest는 공개 저장소에 포함되지 않습니다.
