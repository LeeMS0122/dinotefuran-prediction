# 디노테푸란 예측모델 인수인계

이 문서는 공개 저장소를 처음 받는 개발자를 위한 기술 인수인계입니다. 연구 수치와 완료 상태는 원본 실행의 최종 후보 잠금·평가표·근거 패키지를 대조해 정리했습니다. 공개 저장소에는 원천 데이터, 모델 체크포인트, 개별 예측, DB 접속 설정, 대형 실행 산출물이 없습니다. **아래의 과거 성능은 공개 코드만 실행해 즉시 재현되는 결과가 아니라 검증된 원본 실행의 집계 결과**입니다.

## 1. 문제와 정책

- 목적: 검사 결과가 나오기 전에 이용 가능한 정보로 검사·검토 우선순위를 보조합니다. 모델 예측은 규제상 적합·부적합 판정이 아닙니다.
- 분석 단위: 검사 결과 1건(`record_id`). 통합원장 428,214건에서 `record_id`는 유일했습니다.
- 대상: `occurrence`(잔류 존재), `screening`(검사 결과/MRL > 0.1), `noncompliance`(기준 부적합)를 독립적으로 학습합니다.
- 확정 모집단: 각각 364,864건(양성 17,559건), 67,262건(양성 16,928건), 127,761건(양성 821건)입니다.
- 경계: `screening` 비율이 정확히 0.1이면 음성이고, 0.1을 초과해야 양성입니다. 미확정·수치 미확보 행을 음성으로 대체하지 않습니다. 구현 정책은 `pre_modeling/feature_policy.yaml`을 기준으로 합니다.
- 입력 금지: 검사 결과, 판정, 라벨, 결과/MRL 비율, 사후 날짜 및 라벨 생성과 결합된 현재 MRL 열은 예측 변수에서 제외합니다.

## 2. 분할과 평가

| 구간 | 기간 | 용도 |
|---|---|---|
| 학습 | 2015~2024년 | 전처리 적합과 모델 학습 |
| 검증 | 2025년 | 탐색·후보·임계값 선택 |
| 최종 테스트 | 2026-01-01~2026-06-30 | 고정된 후보의 최종 평가 |

`duplicate_group_id`로 묶인 행은 분할을 넘나들지 않게 합니다. 카테고리·결측 처리도 학습 구간에서만 적합합니다. 검증에서는 가중 F2 최대 지점의 임계값을 정하고 Recall을 우선 검토하되 Precision, F2, AP, 혼동행렬을 함께 봅니다. 서로 다른 목표나 기상 연결 가능 여부가 다른 모집단은 절대 점수로 순위를 매기지 않습니다.

2026년 상반기 결과는 이미 최종 평가에 사용했습니다. 이를 다시 후보 교체, 변수 선택, 임계값 조정에 사용하지 않습니다. 후속 비교는 새로 수집되는 전향자료에서 사전 정의한 기준으로 수행해야 합니다.

## 3. 구현 경로

| 위치 | 역할 |
|---|---|
| `eda/` | 원장 구조·목표·품질 탐색 |
| `pre_modeling/` | 라벨·누수 정책, 학습 대상·분할 설계 |
| `feature_engineering/` | 식품군·원산국·지역·시기 등 내부 변수 구성 |
| `baseline_modeling/`, `official_baseline/` | 초기 모델과 동일 조건 Core-only 비교선 |
| `lstm_data/`, `lstm_baseline/`, `lstm_window_tuning/` | 과거 검사 활동 시퀀스와 14·30·60·90일 창 비교 |
| `external_variables/`, `country_climate_effect/`, `route_climate_effect/` | 기상·기후 연결 및 공급경로 비교 |
| `resources/tuning_experiment_registry.csv`, `tuning/` | 고정된 38개 구성 실험대장과 공통 Optuna 튜닝 |
| `tuning_v2_weather/` | 기상 창 12개 구성의 paired 튜닝·검증 |
| `tests/` | 라벨 경계, 분할, CLI, 결과 정책 단위 테스트 |

2차 정리에서는 노트북 생성 스크립트, 초기 기상 효과·창 탐색 구현, 실험대장 생성 코드, 최종 보고서 조립 코드를 추가로 제외했습니다. 고정된 38행 실험대장은 `resources/tuning_experiment_registry.csv`에 남겼습니다. 이 정리는 과거 수행 결과를 취소한다는 뜻이 아니라 공개본의 범위를 핵심 코드·정책·집계 결과로 좁힌 것입니다. 원장·개별 예측·체크포인트와 최종 근거 패키지는 여전히 비공개입니다. 기상 DB 연결 스크립트는 접속값을 필수 인자로 받고 읽기 전용 트랜잭션을 사용합니다.

## 4. 완료된 모델링

1. EDA·라벨 품질·누수·그룹 시간분할·변수 확장을 수행했습니다.
2. Logistic Regression, CatBoost, LightGBM, XGBoost, LSTM 베이스라인과 LSTM 창 비교를 수행했습니다. 내부 Core 시퀀스 선택은 `occurrence` 90일, `screening` 30일, `noncompliance` 30일이었습니다.
3. 공식 Core-only 비교선으로 5개 모델을 동일 검증 기준에서 비교했습니다.
4. 튜닝 v1은 A1 필수 Core 15개, A2 내부 고도화 12개, B 외부 민감도 11개, 총 38개 구성입니다. 저장된 trial 1,351개 중 1,350개가 완료되고 1개가 실패했습니다.
5. 2025년 검증에서 내부 후보 CFG-010(XGBoost, 잔류 존재), CFG-018(CatBoost, MRL 10% 초과), CFG-031(CatBoost, 기준 부적합)을 잠갔습니다.
6. 기상 v2는 `screening`에 대해 CatBoost·LightGBM·XGBoost × 14·30·60·90일, 총 12개 구성에서 480 trial을 완료했습니다. 동일 국내 연결 가능 시료에서 내부 변수와 기상 추가를 짝지어 비교했습니다.
7. WV2-007(LightGBM, 60일)을 Recall 우선 기상 후보로 잠갔습니다. WV2-003(CatBoost, 60일)은 후속 전향자료에서 확인할 보조 후보입니다.

## 5. 고정 후보의 최종 결과

2025년 검증에서 모델·파라미터·임계값을 고정한 뒤 2026년 상반기 자료에 평가했습니다. 목표마다 평가 대상이 다릅니다.

| 목표 | 후보 | n (양성) | Recall | Precision | F2 | AP |
|---|---|---:|---:|---:|---:|---:|
| 잔류 존재 | CFG-010 · XGBoost | 34,142 (1,532) | 0.7189 | 0.1353 | 0.3859 | 0.2155 |
| MRL 10% 초과 | CFG-018 · CatBoost | 2,375 (436) | 0.8803 | 0.2689 | 0.6051 | 0.3927 |
| 기준 부적합 | CFG-031 · CatBoost | 8,914 (24) | 0.4130 | 0.3220 | 0.3909 | 0.1665 |

공개 집계 근거: `../results/final_model_test_metrics.csv`. 기준 부적합의 테스트 양성은 24건이므로 오차와 불확실성에 유의해야 합니다.

기상 v2의 공통 2026 테스트는 국내 기상 연결 가능 789건(양성 150건)에만 해당합니다. 잠긴 WV2-007은 같은 789건의 내부 대조군보다 Recall이 0.7733 → 0.9600으로 높았고 FN은 34 → 6건이었지만, FP도 337 → 502건으로 증가했습니다. paired bootstrap에서 Recall 차이 95% 신뢰구간은 +0.1267~+0.2467이었고 F2·AP 차이의 신뢰구간은 0을 포함했습니다. 전체 `screening` 모집단 결과나 자동 부적합 판정으로 일반화하지 않습니다. WV2-003은 이 테스트에서 재경쟁시키지 않았습니다.

## 6. 실행과 재현 범위

저장소 루트에서 `conda env create -f environment.yml`로 환경을 만들고 `conda activate dinotefuran` 후 `cd train`을 실행합니다. `.env.example`을 `.env`로 복사한 뒤 접근 권한이 있는 통합원장 경로를 `DINO_EDA_DATA_PATH`에 지정합니다.

```powershell
python -m unittest discover -s tests -p test_*.py -v
python -m tuning --help
python -m tuning_v2_weather --help
python -m tuning status
python -m tuning_v2_weather status
```

새 클론의 `status`에는 원본 환경의 trial이 표시되지 않습니다. `tuning validate`와 전체 재현에는 비공개 원장, 중간 변수·시퀀스·기상 연결 자료가 필요합니다. 특히 B 외부변수 구성을 처음부터 다시 만들려면 공개본에 없는 과거 기상 창 선택 manifest와 연결 산출물도 필요합니다. 고정 실험대장을 공개한 것과 전체 데이터 파이프라인을 단독 재현할 수 있는 것은 다릅니다. 저장된 집계 산출물과 기상 특성자료가 필요한 테스트 2개는 자료가 없으면 skip됩니다. 최종 평가 명령(`evaluate-final`, `evaluate-shared-test`)은 과거 성능을 조회하는 용도가 아니며, 테스트 이력을 새로 만드는 실행으로 취급합니다.

## 7. 한계와 다음 단계

- 통합원장 생성·보강 전체 과정과 외부 기상 DB 접근 권한은 공개 저장소에 포함되지 않습니다. 데이터 없이 원본 최종 지표를 완전 재현할 수 있다고 주장하지 않습니다.
- 국내 기상은 생산지·생산일이 없을 때 수거지·수거일의 대리정보입니다. 수입 기후평년은 실제 검사연도의 기상이 아닙니다.
- 기상 효과는 연결 가능 국내 시료에 한정되며 오탐 증가를 동반합니다. 변수 중요도는 인과효과가 아닙니다.
- 신규 전향자료에서 CFG-018, WV2-007, WV2-003을 사전 정의한 동일 모집단·운영 지표로 재평가하는 것이 다음 단계입니다.

공개본을 변경할 때는 `.env`·원천자료·DB 접속정보·개별 예측·모델 파일을 커밋하지 말고, `git status`와 민감정보 검사를 거친 파일만 명시적으로 스테이징합니다.
